# 03-BACKEND

API 경로, 로그인·권한 확인, 외부 API(Claude·Gemini·구글맵·Unsplash·Open-Meteo) 호출 방식을 정하는 문서입니다.

> 작성: AI · 갱신: 사이클마다

## 1. API 경로

| 경로 | 종류 | 내용 | 단계 |
|---|---|---|---|
| `GET /auth/callback` | 라우트 핸들러 | 구글 로그인 코드를 세션으로 바꾸고 `next`로 보낸다. | v0.2 |
| `signOut` | 서버 액션 | 로그아웃 후 `/login` | v0.2 |
| `devLogin(role, next)` | 서버 액션 | 개발용 로그인. 개발 모드이면서 `DEV_LOGIN=true`일 때만 동작. 로컬 개발 전용으로 계속 둔다(B27). | v0.2 |
| `createTrip` | 서버 액션 | 여행 만들기 후 `/trips/{id}`로 이동. 목적지가 있고 `UNSPLASH_ACCESS_KEY`가 있으면 대표 이미지를 자동으로 넣는다(B47). | v0.3, C7 |
| `renameTrip(tripId)` | 서버 액션 | 여행 이름 수정 | v0.3 |
| `setUploadedCover(tripId)` | 서버 액션 | 브라우저가 Storage `trip-covers/<여행 id>/cover`에 올린 사진을 대표 이미지로 기록한다. 주소는 서버가 만들고 `?v=<시각>`을 붙인다(B51, B52). | C7 (F08) |
| `deleteTrip(tripId)` | 서버 액션 | 여행 삭제. 올린 대표 이미지(`<여행 id>/cover`)도 지운다(실패해도 삭제 진행, B54). | v0.3, C7 |
| `createItem(tripId)` | 서버 액션 | 항목 넣기. 좌표 찾기 후 저장. 폼이 `booking=1`을 보내면 예약 정보를 `item_secrets`에 따로 저장한다(B128) | v0.5, C8 |
| `updateItem(itemId, tripId)` | 서버 액션 | 항목 고치기. 이름·주소·종류가 바뀌었을 때만 좌표를 다시 찾는다. `booking=1`이면 예약 정보도 저장·지운다(B128). | v0.5, C8 |
| `deleteItem(itemId, tripId)` | 서버 액션 | 항목 지우기. 예약 정보는 cascade로 같이 지워진다 | v0.5 |
| `extractItems(tripId, text)` | 서버 액션 | 원문에서 항목 추출. 저장하지 않고 미리보기 항목(추천 표시 포함)과 못 정한 예약번호만 돌려준다. | v0.6, C8 |
| `saveExtractedItems(tripId, form)` | 서버 액션 | 미리보기·추천 카드·대화 제안에서 고른 항목 저장. 좌표 찾기 후 `source = ai` | v0.6, C8 |
| `sendChat(tripId, request)` | 서버 액션 | 대화 도우미 한 턴. 답장·일정 제안·고치기·지우기 제안·추천 칩을 돌려준다. 저장하지 않는다(3절, B114) | C8 (F19) |
| `applyChange(tripId, request)` | 서버 액션 | 대화의 고치기·지우기 카드에서 "반영"·"삭제"를 눌렀을 때만 그 일정을 고치거나 지운다(B120) | C8 (F19) |
| `getOrCreateShareLink(tripId)` | 서버 액션 | 공유 링크가 있으면 돌려주고 없으면 만든다(소유자만, RLS). | v0.9 |
| `GET /share/{token}` | 화면 | 로그인 후 `accept_share`로 등록하고 `/trips/{id}`로 보낸다. | v0.9 |

- 데이터를 쓰는 서버 액션은 입력값만 검사한다. 누가 무엇을 고칠 수 있는지는 RLS가 정한다. RLS에 막히면 바뀐 행이 0개이므로 실패로 처리한다.

- 로그인 없이 열 수 있는 경로는 `/login`, `/auth/callback`뿐이다. 나머지는 `src/proxy.ts`가 `/login?next=원래 경로`로 보낸다.
- `next`는 사이트 안의 경로만 허용한다. 외부 주소면 `/`로 바꾼다.

## 2. 로그인·권한 확인

- 로그인은 Supabase Auth의 구글 로그인으로 한다. v1.0은 구글 계정만 지원한다.
- 권한은 Supabase RLS로 DB에서 막는다. 규칙은 `04-DB.md`에 있다.
- 앱의 데이터 읽기·쓰기는 로그인 사용자 권한으로 접속하는 Supabase 클라이언트로 한다.
- Drizzle로 DB에 직접 접속하지 않는다. 관리자 권한이 되어 RLS가 적용되지 않을 수 있기 때문이다.
- 대표 이미지 올리기(C7, F08)는 브라우저의 로그인 사용자 클라이언트가 Storage에 직접 올리고, Storage RLS가 소유자만 허용한다(`04-DB.md` Storage 절). 서버는 기록만 한다(`setUploadedCover`).
- 여행 목록(C7, F09)은 카드 미리보기용으로 목록의 여행 항목을 한 번에 읽는다(서버 컴포넌트, 같은 RLS). 실패하면 미리보기 없이 목록만 보여 준다.
- 예약 정보(C8, F20): 여행 상세(`page.tsx`)는 소유자일 때만 `item_secrets`를 읽어 항목에 붙인다. 공유받은 사람에게는 읽지 않고 보내지도 않으며, RLS도 소유자만 허용한다(B121, B122). 표가 없으면(반영 전) 예약 정보 없이 보인다.
- 저장 금지 검사(C8, F20): `parseItemForm`이 이름·주소·메모·링크·예약번호에서 저장 금지 정보(카드번호(Luhn)·주민번호·CVC·비밀번호 등)를 찾으면 저장하지 않는다(`src/lib/items/sensitive.ts`, B127).

## 3. AI 추출 호출 (R-04)

- **공급자**: 제공받은 Claude API 키를 먼저 쓰고, 쓸 수 없으면 Gemini 키로 바꾼다.
- **구조**: 공급자를 바꿔도 다른 기능에 영향이 없도록 추출 부분을 한곳에 모아 둔다.
- **흐름**: 붙여넣기 → AI 추출 → 미리보기에서 확인·수정 → 저장
  - 저장은 R-05(직접 입력)와 같은 항목 구조·저장 경로를 쓴다.
- **입력 원문**: 티켓·예약 메일·메모·링크 텍스트
- **원문 처리**: 붙여넣은 원문은 저장하지 않고 추출 결과만 저장한다. "다시 추출하기"는 하지 않는다.
- **초과 방지**: 원문 길이 제한, 사용량 확인, 키는 서버 쪽에만 둔다.
- **주의**: Gemini 무료 등급은 입력 내용이 서비스 개선에 쓰일 수 있다 [가정]. 예시 원문은 개인정보를 가린 것으로만 쓴다.
- 구현(v0.6, `src/lib/extract/`)
  - Claude API는 무료 플랜이 없어 Gemini로 한다(B14). `@google/genai`의 `interactions.create`로 부르고, zod 스키마를 JSON 스키마로 바꿔 `response_format`에 넘긴다. 받은 JSON은 같은 zod 스키마로 다시 검사한다.
  - 모델(B19): `gemini-3.5-flash-lite`를 먼저 부르고, 429·503으로 거절되면 `gemini-3.1-flash-lite`를 한 번 부른다. 한도는 모델마다 따로 센다.
  - 스키마에는 숫자 범위·배열 길이 제한을 넣지 않는다. Gemini가 "too many states"로 거절한다. 일차 범위(1~60)와 항목 수(30개)는 `normalize.ts`에서 맞춘다.
  - 호출 줄이기(B17): 같은 모델로 재시도하지 않는다(`maxRetries: 0`, 60초 제한). 출력 8,192토큰, `thinking_level: "low"`, `store: false`.
  - 보내기 전에 개인정보 모양의 값을 가린다(`mask.ts`, B18). C8(F20)부터는 먼저 링크와 예약번호를 `[링크N]`·`[예약번호N]`으로 바꾸고(`vault.ts`의 `hideForAi`), 결과의 `link`·`booking_ref` 칸에서 원래 값으로 되돌린다. 순서는 `hideForAi` → `maskPersonal`이다(B125).
  - 지시문에 여행 목적지, 시작일·종료일, 일차 수를 넣는다. 원문은 사용자 메시지로 따로 넘기고, 원문 속 지시는 따르지 않도록 한다.
  - 결과는 `normalize.ts`에서 다시 다듬고, 저장 때는 직접 입력과 같은 검사(`validation.ts`)를 거친다.
  - 추천(C8, F18): 스키마에 `suggested_day`·`suggested_time`·`reason`을 더했다. 소유자 확인과 함께 `loadTripContext`가 기존 일정(최대 150개)의 종류·일차·시각·이름·주소를 읽어 `<existing>`으로 보낸다(메모·링크·비용 제외, B111). 일차는 원문 날짜 → 원문 일차 → AI 추천 → 일정이 가장 적은 날, 시각은 원문 → AI 추천(메모 제외) 순이고, 원문에서 온 값이 아니면 `suggest`로 표시한다(B16).
- 대화 도우미(C8, F19, `src/app/actions/assistant.ts`, `src/lib/assistant/`)
  - 붙여넣기/대화 고르기는 화면에서 `routeMessage`(`route.ts`, 점수제)가 한다. 추출은 지금처럼 `extractItems`로 간다(B113).
  - `sendChat`: 입력 검사(zod, 말 1,000자, 대화 기록 최근 10턴, 직전 제안 30개) → `loadTripContext`(소유자만, 기존 일정 150개) → 이번 말·대화 기록·직전 제안·기존 일정 이름/주소를 `hideForAi` → `maskPersonal` → `chatWithGemini`(호출 한 번) → 자리표시 지우기(`stripPlaceholders`) → `normalizeProposal`(새 일정: 범위·중복·시간 겹침·최대 12개) · `normalizeChanges`(고치기·지우기: 번호 확인·쪽지 제외·최대 10건) → Places 확인. 저장하지 않는다(B114~B118).
  - 지시문(`prompt.ts`)은 고정이고, 여행·일차(날짜·요일·숙소)·기존 일정(`#번호`)·직전 제안·대화 기록·이번 말은 태그로 나눠 사용자 메시지로 넘긴다. 모델에게 DB id를 보내지 않고, 번호 → id 표는 서버가 요청마다 만든다(B120).
  - 출력은 `{ reply, items, changes, quick_replies }` 하나다(B115). 출력 4,096토큰, 생각 수준 낮음, `store: false`, 429·503일 때만 다음 모델(B118). 공급자 호출은 `gemini.ts` 한 파일에 둔다(B14).
  - `applyChange`: 카드의 "반영"·"삭제"를 눌렀을 때만 부른다. 일정을 다시 읽어 소유자를 확인하고 `parseItemForm` → `resolvePlace` → update/delete. `booking=1`을 보내지 않으므로 `item_secrets`는 그대로이고, 지우면 cascade로 같이 지워진다. 이미 없는 일정이면 "이미 없는 일정입니다"를 돌려준다(B120, B128).
  - 키: `GEMINI_API_KEY`(서버 전용). 키가 없거나 호출이 실패하면 "추출하지 못했다"는 안내만 보여 준다.

## 4. 구글맵 호출 (R-04, R-05, R-06)

### 4-1. 지오코딩

- 장소 이름이나 주소를 좌표로 바꾸는 단계가 R-04·R-05의 저장 과정에 들어간다.
- 같은 이름의 다른 장소를 피하려고 여행 목적지를 함께 넘겨 검색한다. 미리보기에서 주소를 확인한다.
- 구현(v0.5, `src/lib/items/geocode.ts`)
  - Places API (New) Text Search(`places:searchText`) 한 번으로 찾는다. 검색어는 "주소(없으면 이름) + 여행 목적지", 언어는 한국어, 결과 1개.
  - 받는 값은 좌표와 주소(`formattedAddress`)만 요청한다(`X-Goog-FieldMask`).
  - 대상 종류: 숙소, 관광지, 식당. 교통(출발·도착 두 곳)과 메모는 찾지 않는다.
  - 주소를 비워 두었으면 찾은 주소로 채운다. 사용자가 맞는 장소인지 화면에서 확인할 수 있다.
  - 이름·주소·종류가 그대로이고 좌표가 이미 있으면 다시 호출하지 않는다.
  - 고칠 때 무엇으로 찾을지(`geocodeTarget`): 주소를 새로 넣었거나 고쳤으면(또는 그 주소로 아직 못 찾았으면) 주소로 찾는다. 이름만 고쳤으면 지난번에 자동으로 채운 주소를 버리고 새 이름으로 찾아 주소를 다시 채운다. 이름으로 못 찾으면 주소를 비운다.
  - 나라·도시·동네 같은 지역 결과(`types`에 `political`)는 장소를 찾은 것으로 보지 않는다.
  - 실패(키 없음, 5초 초과, 결과 없음)해도 저장은 한다. 좌표 없이 저장되고 "위치 없음"으로 표시된다.
  - 키: `GOOGLE_MAPS_SERVER_KEY`(서버 전용).
  - 주의: 검색 결과가 없을 법한 이름도 근처의 다른 장소를 돌려줄 수 있다. 그래서 찾은 주소를 화면에 보여 준다. 검색 범위 제한·종류 지정·후보 고르기는 확장 단계에서 다룬다(B13).

### 4-2. 경로 (동선)

- a안: 같은 날의 항목을 "일차 → 시각 → 순서" 기준으로 이어 실제 경로를 계산해 그린다.
- a안 구현이 불가능하면 b안(일차별 색 핀)으로 간다. C4의 첫 작업으로 판정한다. → a안으로 판정(B20).
- 구현(v0.7, `src/lib/map/routes.ts`)
  - Routes API `directions/v2:computeRoutes`, 서버 키. 받는 값은 구간별 거리와 경로 선(`routes.legs.distanceMeters`, `routes.legs.polyline.encodedPolyline`)만 요청한다.
  - 일차마다 자동차 경로 한 번(첫 장소 → 경유지 → 마지막 장소). 결과가 비면 구간마다 대중교통 경로, 그래도 없으면 직선.
  - 결과는 `unstable_cache`로 30일 둔다. 캐시 키는 좌표 목록(소수점 6자리)이라 장소가 바뀌면 새로 구한다(B21).
  - 실패(키 없음, 5초 초과)하면 그 일차는 직선으로 잇고 화면은 그대로 보여 준다.
- 국내 경로: 한국에서는 구글의 도보·자동차 경로가 제한될 수 있다 [가정].
  - 국내도 a안으로 시도한다. 이동 수단을 바꿔(예: 대중교통) 시도한다.
  - 그래도 안 되는 구간의 처리는 C4 계획 단계에서 정한다.

### 4-3. 초과 방지

- API별 일일 할당량을 낮게 제한한다.
- 예산 알림을 설정한다.
- 키를 배포 도메인에서만 쓰도록 제한한다.

## 5. 공유 링크 처리 (R-08)

- 소유자만 공유 링크를 만들 수 있다.
- 링크 식별값은 추측하기 어려운 값으로 만든다.
- 링크로 들어온 사람이 로그인하지 않았으면 로그인으로 보내고, 로그인 후 해당 여행으로 이동시킨다.
- 공유 링크로 들어와 로그인하면 그 사람을 "공유받은 사람"(보기 전용)으로 등록한다.
- 링크를 아는 구글 사용자는 누구나 볼 수 있고, v1.0에는 공유 취소가 없다. 이 점을 소유자에게 안내한다.
- 구현(v0.9): 식별값은 `node:crypto`의 무작위 32바이트(base64url). 등록은 DB 함수 `accept_share` 하나로만 한다(B25). 관리자 키는 쓰지 않는다.
- 로그인하지 않은 사람이 `/share/{token}`을 열면 `proxy`가 `/login?next=/share/{token}`으로 보내고, 로그인 후 돌아와 등록된다.

## 6. 키 관리

- API 키는 서버 쪽과 Vercel 환경 변수에만 둔다. 저장소에 올리지 않는다.

## 7. 외부 서비스 호출 (C7)

### 7-1. Unsplash (대표 이미지, F08)

- 여행을 만들 때만 부른다: 목적지로 검색 1번(가로, 1장, `content_filter=high`) + 쓰기로 한 사진에 다운로드 알림 1번(B47). 기존 여행은 한꺼번에 받지 않는다.
- 사진 파일은 복사하지 않고 주소(`urls.raw`)·대표 색·작가 이름·작가 링크만 저장한다(B48). 화면 크기는 주소 파라미터로 정한다(`coverSrc`, B49).
- 키 `UNSPLASH_ACCESS_KEY`는 서버 전용이다. 없거나 호출이 실패·시간 초과하면 자동 이미지를 건너뛰고 여행은 그대로 만든다.
- 파일: `src/lib/cover/unsplash.ts`, `src/lib/cover/cover.ts`

### 7-2. Open-Meteo (날씨, F10)

- 매거진 GO 카드 줄의 날씨 창. 키·비용 없음. 숙소(없으면 첫 장소) 좌표로 부르고 `unstable_cache`로 3시간 둔다.
- 여행이 16일 안이면 예보, 더 멀면 작년 같은 날짜의 실제 날씨(아카이브)를 "작년 기준"으로 보여 준다(B74).
- 좌표나 시작일이 없거나 실패하면 날씨를 비운다(서버 로그 `weather error`).
- 파일: `src/lib/weather/open-meteo.ts`, `src/lib/weather/codes.ts`
