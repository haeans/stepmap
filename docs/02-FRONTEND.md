## 2. 1·2화면 배치

- 1화면과 2화면은 전환 버튼(일정 / 지도, B183)으로 오간다. 두 화면 모두 오른쪽 위 프로필 버튼 왼쪽에 있다(C9 F23, B180). 지도 탭에서는 반투명 바탕을 깔고, 패널·시트를 접어도 보인다.
- 상단바(C9 F23, B176~B179): 어느 화면에서나 로고는 화면 왼쪽 위, 프로필 버튼은 오른쪽 위(위·옆 16px). 공유 링크 화면은 위에 붙는 흐린 띠, 여행 목록(C9 F21부터, B195)과 일정 화면은 바 없이 배경 위, 지도는 머리글 없이 로고 그림이 패널 안에 있다(B90). 계정·여행 목록·공유·로그아웃은 프로필 메뉴 하나다.
- 1화면은 매거진 한 형식이다. PC와 모바일 모두 매거진으로 연다. "종이"(B안)와 형식 전환 버튼(크게 / 종이)은 C8 F13에서 지웠다(B84).
- 2화면(지도)은 화면 전체를 지도로 채우고, 일정과 버튼은 PC 왼쪽 패널, 모바일 아래 시트에 둔다(3-3절, C8 F14).
- 전환 버튼은 미끄러지는 알약 모양(`Segmented`)이다.
- 위쪽 탭은 일정(매거진) / 지도 두 개다. "리스트" 탭은 시험 후 뺐다(B78).
- 스크롤바는 웹·모바일 모두 숨긴다. 스크롤은 된다(B68).

## 3. 화면 구조 (레퍼런스 기준)

레퍼런스는 화면 구조(어떤 영역이 어떤 순서로 있는지)를 참조한다. v1.0까지는 레퍼런스의 디자인(색, 폰트, 모양, 꾸밈)을 반영하지 않았다(D5). C7부터는 작업 파일에 적은 레퍼런스의 모양도 따를 수 있고, 앱 전체의 색·글꼴·모서리는 6절 디자인 토큰을 따른다(B82).

- 구현(C7, F10): `MagazineView`. 매거진 "크게"가 열려 있는 동안 `<html data-cover>`를 붙여 페이지 바탕색을 사진 톤으로 바꾸고, 머리글·버튼 줄을 흰 글씨로 한다(B64). 배경색은 사진 평균색을 검정 쪽으로 65% 섞는다(B61).
- 대표 이미지가 없으면 목적지 색의 산 능선 SVG(B62). 장소 사진이 없으면 일차 색 그라데이션(B70). 일차 색은 지도와 같다(B63).
- 장소 사진(C8, F22): DAY 장소 카드에 관광지는 Wikimedia Commons, 그 밖은 Google Places 사진(3-5절). 카드 앞면 오른쪽 위에 ⓘ 하나(Google 사진은 옆에 작은 "Google Maps")를 두고, ⓘ를 누르면 사진 크게 보기 창에 출처 전체를 보인다(`PhotoInfo`, B142).
- **C9 구현 (F26 #65)**: DAY 서랍은 `daySchedule`(`src/lib/items/day-plan.ts`, B151) 순서로 카드를 그린다. 첫날은 도착 거점 → 관광지·식당 → 그날 숙소, 마지막 날은 전날 숙소 → 관광지·식당 → 출발 거점, 가운데 날은 관광지·식당만이고 교통 패스·메모는 빠진다. 교통 거점은 `HubCard`(로고, "공항 · 도착", 거점 이름, 교통 이름·출발 시각, 펼침·수정 없음), 시작·끝 숙소는 장소 카드에 `role`을 넘겨 사진이 없으면 로고를 쓴다(B152). F18 추천 카드는 끝 카드 앞에 온다. 빈 날은 "아직 일정이 없습니다".
- **C9 구현 (F28 #69)**: 붙여넣기 추출 결과 중 원문에 일차가 있던 항목은 그 DAY 안 "미리보기" 카드(`PreviewCard`, 점선·흐리게, 사진과 사진 상태 표시)로 보인다. 저장 전이라 하루 일정 규칙을 적용하지 않고 그 일차에 모두 보인다. DAY BY DAY 제목 아래 `PreviewBar`(개수·모두 저장·모두 빼기). 미리보기가 들어오면 그 일차 서랍이 열린다(B184~B188).
- **C9 구현 (F21 #71)**: 대표 사진 전체를 화면에 고정 배경으로 깔고(`CoverLayer`), 사진 평균색(B61)으로 만든 막이 맨 위 25%에서 제목 영역 높이만큼 내려가면 80%로 짙어진다. 위쪽 28%는 흰 글씨용 검정 그라데이션. 지도 탭으로 바꾸면 사진 배경이 사라진다(B192).
- **C9 고침 (F29 #72)**: 시작·끝 숙소 카드 모두 앞면 시각을 숨긴다(서랍 "체크인" 줄은 그대로, B196). 가운데 날에 체크인한 숙소는 그날 끝에 넣고, 그런 여행은 마지막 날을 숙소로 시작하지 않는다(B197, B198). DAY 안 순서는 시작 → 저장된 장소와 미리보기를 시각순으로 섞음(`src/lib/items/merge-by-time.ts`) → 숙소 미리보기(시각 없음) → F18 추천 → 끝이고, "넣기"를 눌러도 카드가 그 자리에 남는다. 첫날·마지막 날 계산에 미리보기 일차를 넣는다(`daySchedule(day, items, pendingDays)`, B199~B201).
- **C10 구현 (F30 #84)**: GO 줄에는 항공권·승차권·숙소·교통 패스만 넣는다. 교통 나누기는 `go-info.ts`의 `transportKind`(항공권 → 교통카드 → 교통 패스 → 개인 교통 → 승차권)이고, 교통카드(ICOCA 등)와 개인 교통(택시·렌터카·리무진·지하철 1회 등)은 GO에 없다(B229~B235). GO 줄은 카드 위에서 마우스로 끌어 옆으로 옮긴다(`useDragScroll`, B237). GO 카드 → DAY BY DAY 제목 간격 40px(B238), 제목 위 목적지 글씨 삭제(B239). GO 카드 오른쪽 위는 "N곳"·"N건"(하나면 비움), 아래 줄은 예약 하나면 날짜(요일) · 시각(숙소는 · N박), 비용 없음(B240, B241).
- **C10 구현 (F30 #84) GO 창**: 항공권 창은 탑승권 모양(모바일 세로 카드, 웹 50rem 가로 표, TO 아래 예약번호, 메모·예약 링크는 본문 맨 아래, 웹 떼는 쪽은 누운 바코드만, 돌아오는 편 줄 없음, B242, B244, B245, B255, B256). 승차권 창은 기차표 모양(실제로 잘라 낸 홈, 한 값은 한 곳에만, 예약번호는 머리 줄 오른쪽 아래, 떼는 쪽은 도착지·안내·DAY 도장, B246~B249, B253, B254). 교통 패스 창은 교통카드 모양(대표 이미지 위 CITY PASS·패스 이름·사용일 한 줄, 아래 띠는 메모만, B250, B251). 숙소 창 위 사진은 숙소 사진(직접 → Google Places → 대표 이미지, B243). 네 창 모두 대표 이미지를 흐리게 깐 뒷배경(`TicketBackdrop`, B252, B255, B257). 색은 전과 같다.
- **C10 구현 (F31 #80)**: 준비물은 DB(`trip_checks`)에 저장한다. `page.tsx`가 서버에서 읽어 `ScheduleView` → `MagazineView` → `Checklist`(`initialChecks`, `readOnly`)로 넘긴다. 더하기·체크·빼기는 화면을 먼저 바꾸고 서버 결과로 맞추며, 실패하면 되돌리고 "준비물을 저장하지 못했습니다"(B207). 30개가 차면 입력 칸 대신 안내(B205). 공유받은 사람은 목록과 체크 상태만 보고 "체크는 여행을 만든 사람이 해요." 안내, 목록이 비어 있으면 칸이 없다(B204). C9까지 브라우저에 있던 준비물은 소유자가 처음 열 때 DB로 옮긴다(B206). "이 브라우저에만 저장돼요" 문구는 없다.

- 구현(C8, F16): GO 카드는 `TicketStrip`의 종류별 묶음이다(`src/lib/trips/go-info.ts`가 항공권·승차권·교통 패스를 이름으로 나눔, B104). 창은 카드 아래 좌우 화살표(키보드 ← →)로 예약을 넘기고, 닫기·수정·삭제는 아이콘 버튼이다(B97). 창은 화면 폭·높이로 키우는 비율을 정해 스크롤 없이 들어오게 한다(B102). 수정 중 바깥을 누르면 고친 것이 있을 때만 묻는다(B105).
- 예약 줄(C8, F20): 소유자에게만 GO 창·장소 카드에 예약번호(`K7••••XM`, "보기")와 예약 링크가 보인다(`BookingInfo`, B126). C9 F26부터 예약 링크는 주소·도메인 없이 "예약 링크 열기 ↗" 버튼만이고, 매거진 DAY 숙소 카드를 펼치면 "체크인" 줄 오른쪽에 둔다(B154). 지도 핀 팝업에는 예약 줄이 없다(B166).
- 장소 카드 비용 줄 이름(C9 F27): 교통 "요금", 숙소 "숙박비", 관광지 "입장료", 식당 "식비", 값이 없으면 "숙박비 정보 없음"처럼(B160).
- 추천 카드(C8, F18): 추천이 들어오면 그 DAY가 펼쳐지고 머리에 "추천 N"이 보인다. 카드는 "넣기"(저장)·"고치기"(저장 전 값만)·"빼기"(추천만 지움). 보기 전용에는 보이지 않는다(B112).
- 장소 카드는 화면에 들어올 때 차례로 떠오르고, 움직임 줄이기 설정이면 움직이지 않는다.

## 4. 이동 흐름

1. 로그인 → 여행 목록 → (새 여행 만들기 또는 선택) → 여행 상세 1화면
   - PC·모바일 모두 매거진으로 열린다(B84).
2. 1화면 → [입력 버튼] → 입력창
   - 붙여넣기 → "매거진에서 보기" → 매거진 DAY의 미리보기 카드 → "넣기"·"모두 저장" → 1화면·지도·비용에 반영(C9 F28). 일차·시각을 원문에서 못 정한 항목은 매거진 추천 카드 → "넣기"로 저장(C8 F18). 준비물은 BACK 체크리스트로 바로 들어간다(C9 F27)
   - 말 걸기("둘째 날 일정 짜 줘") → 대화창의 제안 미리보기 → "저장", 또는 저장된 일정 고치기·지우기 카드 → "반영"·"삭제"(C8 F19). C10 F33부터 새 일정 제안도 매거진 DAY의 미리보기 카드 → "넣기"·"모두 저장"(B223), 고치기·지우기 카드가 2개 이상이면 "전체 반영"·"전체 삭제"·"전체 취소"(B228)
   - C10 F33부터 일차·시각을 AI가 채운 항목도 추천 카드 대신 미리보기 카드(서랍에 "(추천)", B222). 원문 기간이 여행과 다르면 입력창에 기간 맞추기 카드(B224)
   - 직접 입력 → 저장 → 1화면·지도·비용에 반영
3. 1화면에서 장소 카드의 지도 버튼 누르기 → 2화면(지도)으로 넘어가 해당 핀으로 이동
4. 여행 상세 → 오른쪽 위 프로필 메뉴 → [공유] → 공유 창 → 링크 복사 → 닫기 (C9 F23)
5. 공유받는 사람: 공유 링크 열기 → 구글 로그인 → 해당 여행 상세(보기 전용)
   - 이후에는 자기 여행 목록에서 "공유받음"으로 다시 연다.
   - 입력·수정·삭제·공유 버튼은 보이지 않는다.
6. 어느 화면에서든 프로필 메뉴 → 로그아웃 → 로그인 화면

### 5-2. 입력창 (v0.4)

- 오른쪽 아래 입력 버튼으로 연다. PC는 오른쪽 옆 창, 모바일은 아래에서 올라오는 창이다. C8(F17)부터 버튼은 곰발바닥 모양의 둥근 버튼이고 읽기 이름은 "입력창 열기"/"입력창 닫기"다(B108).
- 닫기: 같은 버튼(PC), 창의 ✕ 버튼, Esc 키. 닫으면 포커스가 입력 버튼으로 돌아간다.
- 보내기는 v0.5(직접 입력), v0.6(붙여넣기 추출)에서 연결한다.
- 장소 사진은 출처가 정해질 때까지 빈 자리로 둔다(대표 이미지는 3-5절, `open-questions.md`).
- C7(F10)부터 항목 수정 창은 어두운 유리 패널(`edit-sheet.tsx`, `form-styles.ts`)이다. 입력창은 C8(F17)부터 한지 톤 토큰으로 칠한 밝은 패널이다(B109).
- 창 제목은 "일정 넣기", 아래 탭은 "붙여넣기"(왼쪽, 처음 열 때)와 "직접 입력"(오른쪽). 탭마다 안내·저장 알림·쓰던 내용을 따로 갖고, 탭을 오가거나 창을 닫아도 남는다(B106).
- 직접 입력은 종류마다 필요한 칸만 받는다(B107). 교통은 편명·출발지·도착지를 따로 받아 이름 "KE123 ICN → KIX"로 합쳐 저장하고, 수정할 때 다시 나눈다(B110). 그 종류에 없는 칸은 원래 값을 숨은 칸으로 보내 지워지지 않게 한다.
- 예약 칸(C8, F20): 교통·숙소·식당에 예약번호·예약 링크·링크 공개 범위(자동 / 나만 보기 / 나만 보기·주소 숨김 / 공유한 사람도 보기), 관광지에 예약번호. 메모에는 없다(B121, B124). 예약 칸이 있는 폼만 `booking=1`을 보낸다(B128). 저장 금지 정보가 있으면 저장하지 않고 안내한다(B127).
- 선택 칸(통화, 일차)의 펼친 목록은 흰 바탕·검은 글씨다(B103).

### 5-3. 붙여넣기와 미리보기 (v0.6)

- 붙여넣기 탭에서 원문(최대 5,000자)을 보내면 "추출 중" 말풍선이 뜬다. C8(F19)부터 이 탭은 대화창이다(아래).
- (C9 F28부터) 추출이 끝나면 입력창에는 몇 개를 띄웠는지와 "매거진에서 보기" 버튼만 나오고, 항목은 매거진 해당 DAY의 미리보기 카드로 간다(3-1절, B184~B186). 미리보기 카드의 "고치기"는 직접 입력과 같은 칸(종류, 일차, 시각, 이름, 주소, 메모, 링크, 비용·통화, 예약 칸)이다. "넣기"·"모두 저장"은 source `ai`로 저장하고, 하나라도 입력값이 틀리면 저장하지 않고 알려 준다. 여행 기간 뒤 일차로 뽑힌 항목도 그 일차를 늘려 보인다.
- 같은 원문을 다시 추출하는 버튼은 두지 않지만, 같은 원문도 다시 보낼 수 있다(B17, C8 F18).
- 준비물(C9 F27): "준비물:" 같은 제목 + 짧은 목록이면 AI 없이 BACK 체크리스트에 바로 더하고, 그 밖의 붙여넣기는 추출 결과의 `packing`을 더한다. 말로 이어 적은 목록은 추출로 보낸다(B157, B161).
- 안내(F20 문구: 링크·예약번호는 AI에 보내지 않고, 저장 금지 정보는 가린다, "원문은 저장하지 않습니다.")는 C9 F28부터 늘 펼쳐 두지 않고 "지침" 글자에 마우스를 올리거나 누르면 말풍선으로 보인다. 글자 수 표시는 없다(B18, B125, B189).
- 어느 항목에도 붙지 않은 예약번호는 "어느 항목인지 못 정한 예약번호"로 보인다(B125).
- 추천(C8, F18): 원문에 일차·시각이 다 있는 항목만 미리보기로 간다(C9 F28부터 매거진 미리보기 카드). 일차나 시각을 AI 추천이나 "일정이 가장 적은 날"로 정한 항목은 미리보기 없이 매거진 해당 DAY의 추천 카드로 가고, 입력창에 "추천 N개를 DAY BY DAY에 띄웠습니다"가 보인다(B16, B112). 메모 종류는 추천 카드로 보내지 않고 바로 저장한다. → C10 F33부터 붙여넣기에서는 추천 카드를 만들지 않는다(아래).
- **C10 (F33 #83)**
  - 붙여넣기 결과는 AI가 일차·시각을 채웠어도 모두 매거진 미리보기 카드로 가고, AI 값은 카드 서랍에 "(추천)" 표시와 추천 이유로 보인다. 고치기를 하면 추천 표시를 지운다. 이미 띄운 추천 카드는 남는다(B222).
  - 대화 도우미의 새 일정 제안도 대화창 폼 대신 매거진 미리보기 카드로 띄운다. 대화창에는 답장, 영업시간 확인 안내, "매거진에서 보기"만. 다시 짜 달라고 하면 아직 넣지 않은 앞 제안 카드가 새 제안으로 바뀐다. 예전 대화 기록의 제안 폼은 그대로 보인다(B223).
  - 기간 맞추기 카드: 원문 기간이 여행과 다르면 "원문은 3박 4일(…)인데 여행은 4박 5일(…)이에요. 여행 기간을 원문에 맞출까요?"와 선택지(날짜·기간 모두 / 날짜만 / 기간만 원문대로, 그대로 두기, 지금과 같은 선택지는 숨김). 고르면 `setTripPeriod`로 바꾸고 미리보기를 옮기거나 다시 뽑는다. 없어질 DAY에 저장된 일정이 있으면 바꾸지 않고 알린다(B224).
  - 고치기·지우기 카드가 2개 이상이면 위에 [전체 취소] [전체 삭제 (n개)](고치기가 섞이면 "전체 반영"), 지우기가 있으면 한 번 더 묻는다(B228).
  - "지침" 말풍선 문구: "보낸 내용은 AI(Anthropic Claude, 안 되면 Google Gemini)가 처리하며 Google 쪽에서는 사람이 볼 수 있습니다."(B225).
  - 준비물(C10 F31): 붙여넣기 답은 DB에 더한 결과를 기다려 보이고, 30개를 넘어 못 넣은 개수를 알린다. "이 브라우저에만 저장돼요" 문구는 없다(B205).
- 대화창(C8, F19)
  - 입력칸 하나에 원문을 붙여넣거나 말을 건다. 보내면 `routeMessage`가 추출/대화를 고르고(애매하면 대화), 결과마다 "대화로 다시 보내기 / 붙여넣기로 뽑기"를 둔다(B113).
  - 보낸 말, 도우미 답장, 추출 미리보기, 일정 제안 미리보기(AI 추천 표시, Places에서 못 찾으면 "찾지 못함"·넣기 끔, 영업시간·폐업 안내), 고치기·지우기 카드(바뀌기 전→후 또는 지울 일정, "반영"·"삭제"·"취소"), 다음 말 추천 칩이 위에서 아래로 쌓인다(B116, B117, B120).
  - 제안은 "저장"을, 고치기·지우기는 카드 버튼을 눌러야만 반영된다. 새 제안이 오면 앞의 열린 카드는 닫는다.
  - 대화 기억은 `chat-store.ts`(여행별 localStorage `stepmap:chat:<tripId>`, 최근 40개). "대화 지우기"로 지운다. 추출 미리보기를 저장하거나 닫으면 그 안의 예약 정보는 기록에서 지운다(B119).

### 5-4. 공유와 보기 전용 (v0.9)

- 소유자: 프로필 메뉴의 "공유"(C9 F23, B178. 그 전에는 여행 상세 위쪽 버튼과 지도 로고 메뉴) → 공유 창(링크, 복사 버튼, "링크를 아는 구글 사용자는 누구나 볼 수 있고 취소할 수 없다"는 안내).
- 공유받은 사람: 프로필 메뉴에 "공유받음 · 보기 전용" 표시. 입력 버튼, 공유, 항목 수정·삭제, 여행 이름 수정·삭제가 보이지 않는다. 지도와 쓴 돈은 그대로 본다(정산 인원은 바꿔 볼 수만 있음, B159). C8부터 추천 카드·예약 줄, C9부터 미리보기 카드·줄도 보이지 않는다(B112, B126, B185). 준비물은 C10 F31부터 목록과 체크 상태만 보이고 더하기·체크·빼기는 없다(B204). 예약 정보는 서버가 아예 보내지 않는다.
- 목록: 공유받은 여행은 내 여행과 같은 목록에 섞고 "공유받음" 표시를 붙인다.
- 틀린 공유 링크: "공유 링크가 올바르지 않습니다" 안내와 목록으로 가는 링크.
- 뽑은 항목이 없으면 "찾은 항목이 없습니다"라고 알려 준다.

## 6. 디자인 토큰 (C7, F07)

정의는 `src/app/globals.css`(색·모서리·그림자), `src/app/layout.tsx`(글꼴)에 있다. 새 화면 코드는 아래 토큰을 쓴다(B40).

### 6-1. 색 (한지 톤, B39)

| 토큰 | Tailwind | 라이트 | 다크 | 쓰임 |

| `--surface` | `bg-surface` | `#f5ecda` | `#221e18` | 카드·폼 같은 종이 면 |
| `--muted` | `text-muted` | `#7d6e57` | `#a99c87` | 보조 글자 |
| `--line` | `border-line` | `#d6c3a1` | `#3a3229` | 선·테두리 |

- `white`는 한지 흰색 `#f8f1e3`, `zinc-50`~`zinc-950`은 베이지 회색으로 바꿔 두었다. 기존 화면의 `bg-white`·`zinc-*`도 톤이 맞는다(B40, B46).
- 매거진 "크게"가 열려 있는 동안은 `--background`가 사진 톤으로 바뀐다(B64).
- 다크 모드는 시스템 설정을 따른다. 정식 지원 여부는 `open-questions.md`.

### 6-2. 글꼴 (B42)

### 6-3. 모서리·그림자·상호작용 (B41, B43)

| 모서리 | sm | md | lg | xl | 2xl |
|---|---|---|---|---|---|
| 값 | 0.5rem | 0.75rem | 1rem | 1.25rem | 1.5rem |

- 그림자(`shadow-sm`~`xl`)는 갈색 기운으로 옅고 넓게.
- 키보드 포커스는 `--accent` 2px 테두리. 창(dialog) 뒤는 흐리게. 누를 수 있는 것은 손가락 커서.
