# F19 AI 일정 도우미 2: 대화로 새 일정 짜기 → 허락하면 저장

> 담당: hyunw0000(김현우) · 이슈: #39 · 브랜치: `hyunw0000/f19-ai-planner` · 킥오프: 2026-11-03
> 상태: 반영 완료(2026-11-04, sync PR #52)

## 1. 범위

PRD 4절 C8 F19 ("v1.0 이후 후보"의 "AI 일정 도우미"). F17(#45)·F18(#46) 위에 쌓는다.

1. **입력칸 하나로 붙여넣기와 대화**: 붙여넣기 탭의 입력칸에 티켓·예약 메일을 붙여넣어도 되고, "둘째 날 일정 짜 줘"처럼 말을 걸어도 된다. 보내면 코드(`routeMessage`)가 붙여넣기인지 대화인지 고른다. 모델이 고르지 않는다.
2. **대화창**: 붙여넣기 탭이 대화창이 된다. 보낸 말, 도우미 답장, 추출 결과, 일정 제안이 위에서 아래로 쌓인다.
3. **붙여넣기**는 F18 그대로(추출 지시문·스키마·추천 카드)다.
4. **대화**는 매 턴 호출 한 번으로 답장(`reply`), 일정 제안(`items`), 다음 말 추천(`quick_replies`)을 받는다. 제안은 대화창 안의 미리보기로 보이고, 사용자가 고치고 "저장"을 누르면 그대로 저장한다.
5. **코드가 제안을 검증**한다: 일차·시각 범위, 기존 일정과 같은 장소 빼기, 같은 날 시간 겹침 미루기, 항목 수 상한, Places로 실제 장소 확인(못 찾으면 넣기 끔).
6. **대화 기억**: 서버는 저장하지 않는다. 대화는 여행별로 브라우저 localStorage에 두고, 최근 대화와 직전 제안을 매 턴 함께 보낸다.
7. **(범위 추가, 2026-11-04 팀 승인 · 문서 반영 대기, 6-1절)** 저장된 일정 고치기·지우기: "라멘집 7시로 옮겨 줘", "오사카성 지워 줘"라고 하면 바뀌기 전·후(또는 지울 일정) 카드를 보여 주고, "반영"·"삭제"를 눌러야 반영한다. 고칠 수 있는 칸은 일차·시각·이름·주소·메모.

### 하지 않는 것

- 에이전트(모델이 도구를 골라 여러 번 호출). 메시지 하나에 호출 하나다.
- 쪽지(메모 종류)·준비물·쓴 돈(금액)·여행 자체를 대화로 고치거나 지우기. 일정의 종류·링크 바꾸기.
- 여행과 무관한 일반 대화. 짧게 답하고 여행 이야기로 돌아온다.
- 대화를 DB에 저장, 사람별 하루 횟수 제한(DB 필요, 질문 2).
- 글자가 흘러나오는 응답(스트리밍).

4. **(범위 추가, 2026-11-04 팀 승인, 구현함)** 매거진에 보이는 저장된 일정을 대화로 고치기·지우기(결정 8). 공통 문서(PRD·features)는 아직 "새 일정 짜기"만 적혀 있어 6-1절대로 haeans가 고쳐야 한다. 준비물·쓴 돈·쪽지는 하지 않는다.

#### 구현한 설계 (결정 8과 같음)

- **번호로 가리키기**: 모델에게 보내는 `<existing>` 줄에 짧은 번호(`#1`, `#2`…)를 붙인다. 모델은 번호만 돌려주고, 서버가 번호 → 실제 id로 바꾼다(모델에게 DB id를 보이지 않는다). 번호 → id 표는 서버가 요청마다 새로 만든다.
- **모델 출력**: 지금 `{ reply, items, quick_replies }`에 `changes: [{ ref: "#3", action: "update" | "delete", day, time, name, address, memo }]`를 더한다. update는 바꿀 칸만 채우고 나머지는 null. 호출 수는 그대로(메시지 하나에 한 번).
- **코드 검증** (`proposal.ts`에 함수 추가)
  - 없는 번호, 메모(`memo`) 종류, 한 번에 10개를 넘는 것은 버린다.
  - update: 일차 범위·시각 형식을 맞추고, 같은 날 다른 일정과 시간이 겹치면 새 제안과 같은 규칙으로 미룬다. 바뀐 칸이 없으면 버린다. 이름이나 주소가 바뀌면 Places로 다시 찾아 좌표를 채운다(못 찾으면 "찾지 못함", 반영 끔).
  - 같은 이름이 여러 개인데 사용자가 특정하지 않았으면 고치지 않고 되묻는다(지시문 규칙).
- **화면**: 대화창에 카드로 보인다.
  - 고치기: 바뀌기 전 → 후를 칸별로 보여 주고 "반영"
  - 지우기: 지울 일정(일차·시각·이름)을 보여 주고 "삭제"
  - **버튼을 눌러야만** 반영된다. 반영 후 카드에 "반영했습니다 / 지웠습니다"를 표시한다.
- **저장 경로**: 새 반영 액션 `applyChange`(`src/app/actions/assistant.ts`). 일정을 다시 읽어 소유자인지 확인하고, 직접 입력과 같은 검사(`parseItemForm`)와 좌표 찾기(`resolvePlace`)를 거쳐 update/delete 한다. RLS가 한 번 더 막는다. 새 테이블·칸 없음(DB 변경 없음).
- **지시문**: "저장된 일정은 고칠 수 없다" 문장을 빼고, 고치기·지우기 규칙(번호로만 가리키기, 애매하면 되묻기, 준비물·쓴 돈·쪽지는 다룰 수 없다고 답하기)을 넣는다.
- **하지 않는 것**: 준비물·쓴 돈·쪽지, 여행 자체 고치기·지우기, 되돌리기(반영 전 확인 카드로 대신한다).
- **위험**: 엉뚱한 일정을 고치거나 지울 수 있다 → 번호 검증, 바뀌기 전·후 카드, 버튼 확인으로 막는다. 대화 중에 다른 화면에서 그 일정을 이미 지웠으면 반영이 실패하고 "이미 없는 일정입니다"를 보인다.
