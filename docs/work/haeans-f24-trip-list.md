  - 카드의 버튼 3개(대표 이미지·이름 수정·삭제)를 반투명 ⋯ 메뉴 하나로 (안건 4)

  - DB 칸·제약 바꾸기(`trips.companions`, 목적지·날짜 NOT NULL). 기존 여행에 목적지·날짜가 빈 것이 있어 앱에서만 막는다(B34 추가형)

## 2. 완료 기준

- [x] 목록 제목은 "발자국", 아래 문구는 "흩어진 여행 정보를 한 곳에"이고 여행 개수가 보이지 않는다

- [x] 서버(`parseTripForm`)도 목적지·시작일·종료일이 비면 거절한다(화면 검사를 건너뛰어도)
- [x] 카드 미리보기는 DAY마다 첫 관광지(없으면 그날 첫 일정) 하나와, 그날 일정이 더 있으면 "…"
- [x] 내 여행 카드 오른쪽 위에 반투명 ⋯ 버튼 하나. 누르면 대표 이미지 바꾸기·이름 수정·삭제 메뉴. 공유받은 여행에는 없다
- [x] 메뉴: 바깥 누르기·Esc로 닫힘, 열면 첫 항목에 포커스, Esc로 닫으면 ⋯ 버튼에 포커스, 메뉴를 눌러도 여행으로 들어가지 않음
- [x] `npm run lint`, `npm run typecheck`, `npm test`, `npm run build` 통과

| [haeans-f24-trip-list] 결정 3 | 화면 | ⋯ 메뉴는 지도 메뉴(`MapMenu`, B92)와 같은 방식: 펼침 버튼(`aria-expanded`), 바깥 누르기·Esc로 닫기. 열면 첫 항목에 포커스, Esc로 닫으면 ⋯ 버튼으로. 순서는 대표 이미지 바꾸기 → 이름 수정 → 삭제(빨간 글씨, 지금처럼 확인 창). 올리는 중·지우는 중에는 ⋯ 자리에 그 글자가 보이고 누를 수 없다. 메뉴가 열려 있는 동안 PC 호버 미리보기는 숨긴다(겹침 방지). B53을 고친다. |
| [haeans-f24-trip-list] 결정 4 | 서버 | 필수 칸 검사는 화면(`required`)과 서버(`parseTripForm`) 둘 다 한다. DB 제약은 바꾸지 않는다. 동행 인원은 폼에 와도 읽지 않고 insert에 넣지 않아 DB 기본값 1이 된다. B24의 "동행 인원은 여행을 만들 때 적은 인원" 부분은 F27(정산 버튼)과 함께 고친다. |
