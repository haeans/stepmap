## 1. 범위

PRD 4절 C8 F17 ("v1.0 이후 후보"의 "입력창 개선"). 네 가지를 한다.

1. **밝은 바탕**: 입력창(`input-panel.tsx`)을 어두운 유리 패널(F10)에서 밝은 패널로 바꾼다. 색은 F07 한지 톤을 따른다(`globals.css`의 기존 색 변수를 쓰고 새로 만들지 않는다). 매거진 사진 위(`html[data-cover]`)에서도 읽혀야 한다.
2. **곰발바닥 입력 버튼**: 오른쪽 아래 "＋ 입력" 알약 버튼을 곰발바닥 모양의 둥근 버튼으로 바꾼다. 그림은 코드 안의 SVG로 그리고(이미지 파일·새 패키지 없음), 화면 읽기용 이름 "입력창 열기/닫기"를 단다.
3. **붙여넣기와 직접 입력 분리**: 지금은 한 창에서 탭(붙여넣기/직접 입력)만 바꿔 쓰기 때문에 안내 말풍선과 저장 알림이 섞이고, 열면 늘 "직접 입력"으로 열린다. 한 창 안에 두 칸을 함께 두고 칸마다 따로 갖게 한다(결정 1).
4. **직접 입력 칸 구조 개선**: 종류마다 필요한 칸만 받는다(결정 2). 저장되는 DB 칸과 서버 검증(`ItemInput`)은 그대로 둔다.

### 하지 않는 것

- 추출 미리보기의 일차·시각 추천(F18), 대화로 일정 짜기(F19). F18·F19는 이 작업 위에 쌓는다. 그래서 붙여넣기 창은 나중에 대화 말풍선이 붙을 수 있는 모양으로 둔다.
- 예약번호·예약 링크 칸과 마스킹(F20). F20이 `item-fields.tsx`에 칸을 더하므로 칸 구조는 칸을 더하기 쉬운 묶음으로 만든다.
- 항목 수정 창(`edit-sheet.tsx`, `item-menu.tsx`, `place-card.tsx`, `ticket-strip.tsx`의 수정 화면)의 바탕색. 칸 묶음(`ItemFields`)을 같이 쓰므로 칸 구조 변경은 수정 창에도 보이지만, 창 바탕은 바꾸지 않는다.
- 서버 액션·추출 로직·AI 호출, DB 변경.
- 디자인 마무리(F21)의 로고·첫 화면.

## 2. 완료 기준

- [ ] 입력창 바탕이 밝은 한지 톤이고, 글자·칸·버튼이 PC(1280)·모바일(390), 매거진 사진 위, 지도 탭 위에서 모두 읽힌다. (매거진 사진 위는 AI 확인, 지도 탭 위는 미확인)
- [x] 오른쪽 아래 입력 버튼이 곰발바닥 모양이고, 마우스·키보드로 열고 닫힌다. 화면 읽기 프로그램에 "입력창 열기"/"입력창 닫기"로 읽힌다.
- [x] 붙여넣기와 직접 입력이 각자의 창으로 열리고, 한쪽의 안내·저장 알림·입력 중인 내용이 다른 쪽에 보이지 않는다.
- [ ] 직접 입력 칸이 바뀐 구조로 보이고, 5종(교통·숙소·관광지·식당·메모)을 모두 저장하면 1화면의 해당 영역에 들어간다(v0.5 회귀).
- [ ] 붙여넣기 → 추출 → 미리보기 → 저장이 그대로 된다(R-04). 같은 원문은 실패했을 때만 다시 보낸다(B17). 개인정보 안내가 그대로 있다(B18).
- [x] 닫기: 같은 버튼(PC)·✕·Esc. 닫으면 포커스가 입력 버튼으로, 열면 첫 입력칸으로 간다(v0.4 회귀).
- [ ] 공유받은 사람에게는 입력 버튼이 보이지 않는다(R-08).
- [ ] 항목 수정 창에서도 바뀐 칸 구조로 수정·저장이 된다.

## 6. 질문

1. ~~"같은 창을 쓰는 문제"를 어떻게 나눌까?~~ → (가)로 정함(결정 1).
   - (가) 곰발바닥 버튼을 누르면 작은 선택지 두 개("붙여넣기", "직접 입력")가 펼쳐지고, 고른 쪽이 각자의 창(제목·안내·알림 따로)으로 열린다. 창 안의 탭은 없앤다. F19 대화는 붙여넣기 창에 붙인다.
   - (나) 창은 하나로 두고 탭을 유지하되, 탭마다 안내·알림·입력 중 내용을 따로 기억하고 마지막에 쓴 탭으로 연다.
   - (다) 버튼을 두 개 둔다(곰발바닥 = 붙여넣기, 옆의 작은 버튼 = 직접 입력).
2. ~~직접 입력 칸 구조는 어떻게 바꿀까?~~ → (가)로 정함(결정 2).
   - (가) 위에는 늘 보이는 칸(종류, 이름, 일차·시각), 아래 "더 보기"를 열면 주소·메모·링크·비용. 종류에 따라 이름 칸의 이름과 예시를 바꾼다(교통: "편명·노선", 숙소: "숙소 이름", 시각은 숙소일 때 "체크인 시각"). 저장되는 값은 그대로다.
   - (나) 칸은 모두 보이게 두고 순서와 묶음만 정리한다(종류 → 이름 → 일차·시각 → 주소 → 비용 → 메모·링크).
3. ~~곰발바닥 그림~~ → 단순 SVG로 정함(결정 3).
5. 교통의 도착 시각, 숙소의 체크아웃 일차처럼 지금 DB 칸에 없는 값을 따로 받을지. 받으려면 DB 변경이 필요해 F17(DB 변경 없음) 밖이다. 다음 킥오프에서 정할지 팀 확인.
4. 수정 창(어두운 유리)도 밝은 바탕으로 맞출지. 이번 범위 밖으로 두었다. F16·F21에서 정할지 팀 확인.
