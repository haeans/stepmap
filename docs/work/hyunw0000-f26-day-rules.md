## 1. 범위

- PRD 4절 C9 1단계 F26 (안건 9, 11, 14). 묶음 B의 첫 작업이고 F25·F28이 이 작업의 하루 일정 규칙 함수를 쓴다.
- 하는 것
  - 하루 일정 규칙: 교통 거점(공항·기차역·버스터미널)과 숙소는 여행 첫날의 시작·끝과 마지막 날의 시작·끝에만 넣고, 가운데 날과 하루 중간의 교통·숙소는 일정에 넣지 않는다. `src/lib/items/day-plan.ts`의 순수 함수 `daySchedule`로 만들고 매거진 DAY BY DAY에 적용한다.
  - 사진 대체: 시작·끝 카드(공항·역·터미널·숙소)에서 사진을 못 불러오면 일차 색 그라데이션 대신 로고(`/brand/logo.png`)를 쓴다.
  - 항공권·승차권 나누는 기준을 정하고 GO 카드·지도 거점·AI 지시문에 같은 기준을 쓴다(regression C8-1).
  - 예약 링크: 주소(도메인 표시, "주소 보기")를 없애고 "예약 링크 열기" 버튼만 둔다.
- 하지 않는 것
  - 지도 핀에 하루 일정 규칙 적용(F25가 `daySchedule`을 가져다 쓴다). 지도 동선(`route-plan.ts`)은 고치지 않았다.
  - 교통 종류 DB 칸, 입력 칸에서 GO 카드 종류 고르기(regression C8-1 고칠 방향 ③). 킥오프에서 DB 칸은 만들지 않기로 했다.
  - 데이터, GO 예약 카드(항공권·승차권·숙소·패스), 쓴 돈은 그대로다.
  - 추출 미리보기에 사진 넣기(F28).

## 4. 결정 (임시 번호)

| 번호 | 영역 | 결정 |
|---|---|---|
| [hyunw0000-f26-day-rules] 결정 1 | 화면·규칙 | 하루 일정은 그날의 관광지·식당(일차 → 시각 → 순서)이다. 교통 거점과 숙소는 여행의 첫날과 마지막 날에만 넣는다(2026-11-04 hyunw0000 확인: "호텔이나 항공은 DAY 1과 DAY N에만"). **첫날**: 시작은 그날 첫 교통의 도착 거점(간사이 공항), 끝은 그날 체크인한 숙소. **마지막 날**: 시작은 전날 밤 숙소(그날보다 앞서 체크인한 마지막 숙소), 끝은 그날 마지막 교통의 출발 거점. **가운데 날**: 관광지·식당만(도시를 옮기는 날의 신칸센·새 숙소도 넣지 않음). 첫날·마지막 날은 일정(메모 빼고)이 있는 처음·마지막 일차다. 하루짜리 여행은 도착 거점 → 장소 → 출발 거점. 교통 패스·메모는 넣지 않는다. 그날 일정이 없으면 빈 목록. 좌표는 보지 않는다(거점 좌표는 지도가 `hub-lookup.ts`로 찾는다). B12의 DAY 영역, B132(지도 선의 시작·끝)를 고친다. |
| [hyunw0000-f26-day-rules] 결정 2 | 화면 | 시작·끝 카드: 숙소는 기존 장소 카드와 같이 왼쪽 위에 시각(마지막 날 아침의 시작 숙소는 체크인 시각이 전날 것이라 숨김). "하루 시작/끝" 글자는 두지 않는다(2026-11-04 hyunw0000: 시간으로). 사진(직접 넣은 사진 → 장소 사진)을 못 불러오면 로고. 교통 거점은 따로 저장된 장소가 아니라서 거점 카드(로고, 출발 거점은 왼쪽 위에 출발 시각·도착 거점은 시각 없음(도착 시각을 저장하지 않음), "공항·역·터미널 · 도착/출발", 거점 이름 "간사이 공항", 교통 이름·출발 시각)로 보이고 펼침·수정은 없다(교통은 GO 카드에서 고친다). 거점 이름은 F15 검색어 규칙(`hubQuery`)과 같다. 비행기는 공항 코드를 한국어 공항 이름으로 바꿔 쓴다. |
| [hyunw0000-f26-day-rules] 결정 3 | 규칙 | 항공권·승차권 기준. 교통 항목은 ① 화살표 양쪽이 공항 코드(`ICN → KIX`) ② 편명(`KE723`, `7C1301`)이나 항공·비행·flight·airline 같은 말이 있고 기차·버스·배 말(역·열차·기차·철도·신칸센·KTX·SRT·버스·터미널·페리·지하철·택시 등)이 없음 ③ 화살표 양쪽이 모두 아는 공항(이름 또는 "○○공항": `인천 → 간사이`) 중 하나면 항공권. "공항" 한 낱말만으로는 비행기로 보지 않는다(공항철도·공항버스). 그 밖은 패스 말(B104)이 있으면 교통 패스, 아니면 승차권. GO 카드(`go-info.ts`)와 지도 거점(`hubs.ts`)이 같은 `isFlight`를 쓴다. 공항 이름은 코드로 바꿔 보이고(인천 → ICN), 모르는 이름은 그대로(오사카). 교통 종류 DB 칸은 만들지 않는다. B104, B131을 고친다. |
| [hyunw0000-f26-day-rules] 결정 4 | 화면 | 예약 링크는 주소·도메인을 보이지 않고 "예약 링크 열기 ↗" 버튼만 둔다. owner·secret 단계 모두 같다. 예약번호(앞뒤 두 글자, "보기")와 공유받은 사람에게 예약 줄이 없는 것은 그대로다. 고치기 창의 예약 링크 입력 칸은 그대로 원래 주소를 보인다(고쳐야 하므로). B126을 고친다. |
| [hyunw0000-f26-day-rules] 결정 5 | AI | 추출·대화 도우미 지시문: 비행기 이름은 `편명 출발공항코드→도착공항코드`(`KE723 ICN→KIX`), 코드를 모르면 공항 이름. 열차·버스는 `KTX 101 서울→부산`, 교통 패스는 화살표 없이 원래 이름. |
