## 1. 범위

PRD 4절 C10 F33 ("v1.0 이후 후보"의 "AI 추출·대화 도우미에 Claude API 추가(Gemini 유지)").

- 붙여넣기 추출(R-04, F18)과 대화 도우미(F19)가 Claude API(`claude-sonnet-5-5`)를 먼저 부른다. `ANTHROPIC_API_KEY`가 없거나 Claude 호출이 실패하면 지금의 Gemini 호출(두 모델, B19)로 넘어간다.
- 2026-11-05 팀 승인으로 F33에 더한 것(hyunw0000 요청, PR 승인 때 다시 확인): 결정 5(붙여넣기 결과는 모두 미리보기), 결정 6(대화 제안도 매거진 미리보기), 결정 7(원문에 맞춰 여행 기간·날짜 맞추기), 결정 8(지침 문구), 결정 9(미리보기에도 하루 일정 규칙, 비행기 공항 먼저), 결정 10(거점 이름 한국어), 결정 11(고치기·지우기 전체 반영).
- Gemini에 쓰던 것을 그대로 Claude에도 쓴다: 같은 지시문(`SYSTEM_PROMPT`, `CHAT_SYSTEM_PROMPT`), 같은 입력(`userMessage`, `chatMessage`), 같은 응답 스키마(`ExtractSchema`, `ChatSchema`), 같은 가리기(`hideForAi`, `maskPersonal`)와 정리(`normalizeItems`, `normalizeProposal`, `normalizeChanges`).

### 하지 않는 것

- 지시문(`src/lib/extract/prompt.ts`, `src/lib/assistant/prompt.ts`) 수정. F30과 겹치지 않게 고치지 않는다(킥오프 "C10 진행 순서"). 기간 맞추기도 지시문을 고치지 않고 원문·추출 결과로 판단한다(결정 7).
- DB 변경(없음). 기간 맞추기는 지금 있는 `trips.start_date`·`end_date`와 `items.day`만 고친다.
- Vercel 환경 변수 등록과 팀원에게 키를 공유하는 일(haeans, B30).

AI가 여행 기간 밖 날짜를 버리는 일이 있어서다(2월 여행에 "11/20" → null). 연도가 없으면 여행 앞뒤 일주일 안의 해, 아니면 오늘 기준 다가오는 날짜로 본다. 원문 날짜가 여행과 일주일 넘게 떨어져 있으면(2월 여행에 11월 원문) "N박 M일"이 없어도 길이를 지키며 원문 날짜로 옮기자고 묻는다. 원문과 여행의 연도가 다르면 화면에 연도도 적는다. [맞추기](`setTripPeriod`): 원래 기간과 새 기간이 겹치면 저장된 일정은 날짜를 지킨다(시작일이 옮겨진 만큼 일차를 옮김). 겹치지 않으면(2월 여행을 11월로) DAY 번호를 지킨다(`shiftForPeriod`). 새 기간 밖으로 나가는 일정(메모 제외)이 있으면 바꾸지 않고 "DAY 5에 2개"처럼 알린다. 메모는 기간 안으로 당긴다. 저장 전 미리보기도 같은 만큼 옮기고, 원문이 화면 메모리에 있으면 이번 미리보기를 내리고 새 기간으로 다시 뽑는다. 일정 일차 고치기와 기간 고치기는 한 번에(트랜잭션) 묶이지 않는다(DB 함수가 필요해 DB 변경이 됨). 일정 고치기가 실패하면 기간은 바꾸지 않는다. |
