# F31 준비물을 DB에 저장

> 담당: haeans · 이슈: #76 · 브랜치: `haeans/f31-checklist-db` · 킥오프: 2026-11-05 (C10, PR #79)
> 상태: 작업 중 (마이그레이션 반영 전)

## 1. 범위

- PRD 4절 C10 F31 (fix8). **DB 변경 있음** (새 테이블 `trip_checks` + RLS, 추가형).
  - 준비물 체크리스트를 브라우저(localStorage)가 아니라 DB에 저장한다. 기기를 바꿔도 남는다.
  - "준비물은 이 브라우저에만 저장돼요" 안내 문구를 지운다(BACK 패널, 붙여넣기 답).
- 작업 중 더한 것 (2026-11-05 haeans, 3인 구두 합의 → 이 PR의 승인으로 확인)
  - 공유받은 사람도 준비물을 **보기만** 한다(같이 챙기는 목록). 더하기·체크·빼기는 소유자만. B76·B100의 "공유받은 사람에게는 보이지 않는다"를 고친다. (결정 2)
  - 여행 하나에 준비물 30개까지 (결정 3)
- 진행 순서: 킥오프 표는 F30 → F31이지만 haeans가 F31을 먼저 한다(같은 담당이라 다른 작업에 영향 없음). F30은 F31 머지 뒤 최신 `main`에서 판다(`ticket-strip.tsx`가 겹침).
- 하지 않는 것
  - 공유받은 사람의 체크·더하기(쓰기 권한). 보기 전용 원칙(R-08)을 바꾸는 일이라 다음 킥오프 안건으로 둔다
  - 사람마다 따로 체크하기(목록은 여행에 하나)

## 2. 완료 기준

- [x] 준비물은 `trip_checks`에 저장되고, 새로 고치거나 다른 기기·브라우저에서 열어도 남는다 (반영 후 확인)
- [x] 더하기·체크·빼기는 화면이 바로 바뀌고, 저장에 실패하면 되돌리고 이유를 보인다
- [x] 붙여넣기("준비물: 여권, 우산", 추출 결과 `packing`)도 DB에 더하고 BACK 패널에 바로 보인다. 이미 있는 이름은 건너뛴다
- [x] 여행 하나에 30개까지. 다 차면 입력 칸 대신 안내, 붙여넣기는 못 넣은 개수를 알린다. DB 트리거도 막는다
- [x] C9까지 이 브라우저에 저장된 준비물은 소유자가 처음 열 때 DB로 한 번 옮기고 브라우저 값을 지운다(DB가 비어 있을 때만)
- [x] 공유받은 사람: 목록과 체크 상태를 본다. "＋ 준비물 추가"·체크·✕가 없고 "체크는 여행을 만든 사람이 해요." 안내. 목록이 비어 있으면 칸이 없다
- [x] "준비물은 이 브라우저에만 저장돼요" 문구가 없다
- [x] 마이그레이션은 추가형(새 테이블만). 반영 전에도 지금 배포본이 그대로 동작한다
- [x] `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`

## 3. 바꾸는 곳

| 층 | 파일 | 내용 |
|---|---|---|
| DB | `src/db/schema.ts` | `tripChecks`(`trip_checks`): id, trip_id(여행 삭제 시 함께), label(1~40자), done, position, created_at, updated_at. RLS: 보기는 소유자 또는 공유받은 사람, 더하기·고치기·지우기는 소유자 |
| DB | `drizzle/0012_trip_checks.sql`(`db:generate`) | 테이블·제약·색인·RLS 정책 |
| DB | `drizzle/0013_trip_checks_grants.sql`(직접 씀) | 권한(authenticated만, anon 없음), `updated_at` 트리거, 여행당 30개 제한 트리거 `trip_checks_limit` |
| 서버 | `src/app/actions/checklist.ts`(새 파일) | `addChecks`(이름으로 더함, 중복 건너뜀, 30개까지), `setCheckDone`, `removeCheck`, `importChecks`(브라우저 값 한 번 옮기기, DB가 비었을 때만). 모두 로그인한 사용자 권한, 바뀐 뒤 목록 전체를 돌려줌 |
| 서버 | `src/lib/trips/checks.ts`(새 파일) | `readChecks`: 여행의 준비물 목록(위치·만든 순) |
| 규칙 | `src/lib/trips/packing.ts`(+ 테스트) | `CHECKLIST_MAX = 30`, `mergePacking`이 30개까지만 채우고 못 더한 개수(`full`)를 돌려줌 |
| 화면 | `page.tsx` → `schedule-view.tsx` → `magazine-view.tsx` | 서버에서 준비물을 읽어 넘김. 공유받은 사람도 목록이 있으면 BACK에 준비물 칸 |
| 화면 | `checklist-store.ts` | localStorage 저장을 지우고 여행별 목록을 메모리에 들고 서버 액션을 부름(화면 먼저 바꾸고 서버 결과로 맞춤, 늦게 온 앞 요청 결과는 버림). 옛 브라우저 값 옮기기 `moveBrowserChecklist` |
| 화면 | `ticket-strip.tsx` `Checklist` | `initialChecks`·`readOnly` 받음, 30개 차면 안내, 저장 실패 문구, 공유받은 사람은 보기만, 안내 문구 삭제 |
| 화면 | `paste-extract.tsx` | 준비물 더하기를 기다려 결과로 답함. "이 브라우저에만 저장돼요" 삭제, 30개 넘어 못 넣은 개수 안내 |

## 4. 결정 (임시 번호)

| 번호 | 영역 | 결정 |
|---|---|---|
| [haeans-f31-checklist-db] 결정 1 | DB | 준비물은 새 테이블 `trip_checks`에 한 줄씩 둔다(trips에 JSON 칸을 두지 않음). 체크 하나만 바꿀 수 있고, RLS를 다른 표와 같은 방식(`ownsTrip`, `isMember`)으로 건다. 순서는 `position`(더한 순) |
| [haeans-f31-checklist-db] 결정 2 | 화면·DB | 공유받은 사람도 준비물을 본다(2026-11-05 3인 구두 합의, "같이 준비하는 목록"). 보기만 하고 더하기·체크·빼기는 소유자만(RLS 보기 정책에만 `isMember`). 공유받은 사람의 쓰기는 R-08 보기 전용을 바꾸는 일이라 하지 않는다. B76·B100 고침 |
| [haeans-f31-checklist-db] 결정 3 | 서버·DB | 여행 하나에 준비물 30개까지(2026-11-05 haeans). 앱(`mergePacking`)과 DB 트리거(`trip_checks_limit`) 둘 다 막는다. 붙여넣기에서 넘친 것은 넣지 않고 개수를 알린다 |
| [haeans-f31-checklist-db] 결정 4 | 화면 | C9까지 브라우저에 저장된 준비물은 소유자가 매거진을 처음 열 때 DB로 한 번 옮기고 브라우저 값(`stepmap:checklist:<여행 id>`)을 지운다. DB 목록이 이미 있으면 넣지 않고 지우기만 한다. 실패하면 브라우저 값을 남기고 다음에 다시 한다 |
| [haeans-f31-checklist-db] 결정 5 | 화면 | 더하기·체크·빼기는 화면을 먼저 바꾸고 서버가 돌려준 목록으로 맞춘다. 실패하면 서버 목록(없으면 바꾸기 전)으로 되돌리고 "준비물을 저장하지 못했습니다" 안내. 체크할 때마다 페이지를 다시 그리지 않는다(`revalidatePath` 없음) |
