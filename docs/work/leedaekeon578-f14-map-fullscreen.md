## 2. 완료 기준

- [ ] 지도 탭에서 머리글 아래 화면이 지도로 꽉 찬다 (PC·모바일, 가로 스크롤 없음)
- [ ] PC는 왼쪽 패널에 일차 고르기·장소 목록·이전/다음이 있다. 모바일은 아래 시트에 일차 고르기·장소 목록이 있고 이전/다음은 없다 (결정 11 고침)
- [ ] 핀(또는 목록의 장소)을 누르면 세부(이름·종류·시각·주소·메모·비용·링크)가 보인다. PC는 패널 아래 카드, 모바일은 목록 줄 아래에 펼쳐진다. 모바일에서 핀을 누르면 시트가 펼쳐지고 그 줄까지 스크롤된다 (결정 11)
- [ ] 일차를 고르면 그 일차의 핀·선은 진하게, 다른 일차는 흐리게 남는다
- [ ] 지도를 옮길 때 패널에 가린 곳을 빼고 핀이 보인다
- [ ] 지도 탭에 들어가면 현재 시각에 가장 가까운 일정의 핀이 골라진다 (결정 3). `?item=`이 있으면 그 핀이 먼저다
- [ ] 모바일 "+ 입력" 버튼: 접힘에서는 지도 위 오른쪽 아래에 떠 있고 손잡이와 겹치지 않는다. 펼침에서는 목록을 끝까지 스크롤해도 장소를 가리지 않는다 (결정 2 다시 고침)
- [ ] 기존 지도 기능 유지: 일차별 색 번호 핀, 실제 경로 선, 구간 거리·이동 수단, 위치 없는 장소 수 안내, 매거진에서 "지도에서 보기"로 들어오기(R-07)
- [ ] `npm run lint`, `npm run typecheck`, `npm test`, `npm run build` 통과

추가 변경(결정 6~11)

- [ ] 지도 탭에서 맨 위 머리글이 보이지 않고 지도가 화면 맨 위부터 맨 아래까지 채운다. 매거진 탭의 머리글은 그대로다
- [ ] 매거진/지도 전환 버튼이 ROUTE 패널 오른쪽 위에 있다. PC는 패널을 펼쳤을 때, 모바일은 시트를 펼쳤을 때만 보인다 (결정 7 고침)
- [ ] 지도 오른쪽 위에 작은 로고가 있고, 누르면 이메일·여행 목록·공유·로그아웃 메뉴가 열린다. 바깥을 누르거나 Esc를 누르면 닫힌다. 보기 전용에는 공유 대신 "공유받음 · 보기 전용"이 보인다
- [ ] 로고와 지도 확대/축소 버튼이 겹치지 않는다 (PC·모바일)
- [ ] PC: 패널 오른쪽 가장자리의 여닫이 버튼으로 패널을 접고 편다. 접으면 지도가 화면 전체를 쓰고, 화면 왼쪽 끝에 다시 펴는 버튼(›)만 남는다. 매거진/지도 전환 버튼은 남지 않는다 (결정 7 고침)
- [ ] PC: 패널을 접거나 펴면 핀 위치를 맞추는 왼쪽 여백도 바뀐다 (접힘 상태에서 고른 핀이 화면 가운데 쪽에 온다)
- [ ] 모바일: 시트 위쪽 손잡이를 누르거나 위·아래로 밀면 목록이 펼쳐지고 접힌다. 손잡이의 누르는 곳은 128×44px 이상이다 (결정 11)
- [ ] 모바일 접힘: 손잡이만 보이고 ROUTE 제목 줄·전환 버튼·일차 고르기·목록·카드는 보이지 않는다 (결정 11 다시 고침)
- [ ] 모바일 펼침: ROUTE 제목 줄(전환 버튼 포함), 일차 고르기, 장소 목록이 보이고, 목록이 한 줄로 쭉 이어져 시트 안에서 스크롤된다. 목록과 카드가 겹쳐 보이지 않는다 (결정 11 고침)

| [leedaekeon578-f14-map-fullscreen] 결정 1 | 지도 (F15에서 구현) | 교통 거점 좌표는 DB에 저장하지 않고 지도를 그릴 때 서버에서 찾는다. B11의 예정 메모("교통 항목도 도착지 좌표를 찾음")와 다르다. 칸이 `lat/lng` 하나뿐이라 출발지를 담을 수 없어 떠나는 날 동선의 끝(출발 공항·역)을 그릴 수 없기 때문이다. 이렇게 하면 DB 변경이 없고, 이미 저장된 여행에도 바로 적용되며, 항목 저장(`store.ts`)을 고치지 않아 F18·F19와 겹치지 않는다. **호출 수**: 교통 항목마다 출발·도착 검색어 2개를 만들고, 검색어마다 Places Text Search를 최대 1번 부른다(다시 시도하지 않음). 한 여행 안에서 같은 검색어는 한 번만 부른다(예: 가는 편 `ICN→KIX`와 오는 편 `KIX→ICN`은 2번). 교통 항목은 일정 순서로 앞 20개까지만 거점을 찾는다. 그래서 **여행 하나를 처음 열 때 최대 40번**이고, 캐시가 살아 있는 동안 다시 열면 0번이다. 21번째 교통 항목부터는 거점 없이 지금처럼 그린다. **캐시**: 경로 캐시(B21)와 같은 Next.js `unstable_cache`를 쓰고, 키는 `["hub-geocode-v1", 검색어]`, 보관은 30일이다. 키에 여행 id를 넣지 않으므로 여러 여행이 캐시를 함께 쓴다("인천 공항"은 한 번만 찾음). 찾는 결과가 없는 것(null)도 캐시해 같은 검색어를 다시 부르지 않는다. 호출이 실패하면(시간 초과·4xx·5xx) 캐시하지 않고 그 구간만 거점 없이 그린 뒤 다음에 열 때 다시 시도한다. 교통 항목 이름을 고치면 검색어가 바뀌어 새로 찾는다. |
