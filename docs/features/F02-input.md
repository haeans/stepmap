# F02 입력창·직접 입력

버튼으로 여는 입력창과 직접 입력·수정 기능의 명세입니다.

> 사이클: C2 · R-번호: R-03, R-05 · 작성: AI · 갱신: 해당 사이클
> 상태는 `features/README.md`에서 관리한다.

## 1. 범위

- R-03 버튼으로 여는 입력창
- R-05 직접 입력·수정
- 이 사이클에서 항목 구조(비용 칸 포함)와 저장 경로를 확정한다. F03(자동 추출)과 F05(비용 합계·정산)가 이를 재사용한다.

## 2. R-03 버튼으로 여는 입력창

- **동작**: 평소에는 닫혀 있고, 버튼을 누르면 채팅 모양의 입력창이 열린다.
- **완료 기준**: 버튼으로 열고 닫힌다.
- **의존**: R-02

## 3. R-05 직접 입력·수정

- **동작**: 입력창에서 직접 입력하고, 들어간 항목을 고치거나 지운다.
- **완료 기준**: 모든 종류(5종)의 항목을 넣고, 고치고, 지울 수 있다.
- **의존**: R-03

## 4. 공통 처리

- 장소 이름이나 주소를 좌표로 바꾸는 단계(지오코딩)가 저장 과정에 들어간다.
- 지오코딩할 때 여행 목적지를 함께 넘겨 검색한다.

## 5. 관련 화면 (`02-FRONTEND.md`)

- 입력창: 버튼으로 여닫는 채팅 모양 창. 붙여넣기 또는 직접 입력
- 여행 상세 1화면: 일차별 항목, 고치기·지우기
- 흐름: 1화면 → [입력 버튼] → 입력창 → 직접 입력 → 저장 → 1화면·지도·비용에 반영

## 6. 관련 데이터 (`04-DB.md`)

- 일정 항목: 소속 여행, 일차, 시각, 같은 날 안의 순서, 종류, 이름, 주소·좌표, 메모, 링크, 비용(금액·통화, 선택 입력), 입력 방식(직접 / AI)
- 종류: 교통·숙소·관광지·식당·메모 5종
- 항목은 소유자만 만들고, 고치고, 지울 수 있다.

## 7. 관련 결정 (`decisions.md`)

- D4: 항목 종류는 교통·숙소·관광지·식당·메모 5종이다. 그 외는 확장 단계에서 다룬다.

| DB | `src/db/schema.ts`, `drizzle/0003~0004` | `items` 테이블, RLS 정책 4개, 권한, 트리거 (`04-DB.md` 8절) |

1화면 영역에 들어가는 항목:

| 영역 (A안 / B안) | 항목 |
|---|---|
| GO / 교통·숙소 요약 | 교통, 숙소 (모든 일차) |
| DAY N | 그 일차의 관광지, 식당 |
| BACK 쪽지 / 아래쪽 쪽지 | 메모 |
| BACK 쓴 돈 / 아래쪽 쓴 돈 | 비용이 있는 모든 항목 |

- 여행 기간보다 뒤 일차의 항목이 있으면 DAY를 늘려서 보여 준다(여행 날짜를 줄여도 항목이 사라지지 않게).
- 날짜가 없는 여행은 DAY 1~10 중에서 고를 수 있다.
- 같은 날 안의 순서(`position`)는 넣은 순서다. 일차를 바꾸면 그 날의 맨 뒤로 간다. 순서를 끌어서 바꾸는 기능은 없다.
