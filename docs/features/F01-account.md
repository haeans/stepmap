# F01 계정·목록

구글 로그인과 여행 목록 기능의 명세입니다.

> 사이클: C1 · R-번호: R-01, R-02 · 작성: AI · 갱신: 해당 사이클
> 상태는 `features/README.md`에서 관리한다.

## 1. 범위

- R-01 구글 로그인
- R-02 여행 목록
- 이 사이클은 이후 모든 기능의 권한 기반이 된다.
- 공유(R-08)는 F06에서 다룬다.

## 2. R-01 구글 로그인

- **동작**: 로그인·로그아웃. 로그인해야 사용할 수 있다.
- **완료 기준**: 자기 여행만 보이고, 자기 여행만 고칠 수 있다.
- **의존**: 없음
- **제한**: v1.0은 구글 계정만 지원한다.

## 3. R-02 여행 목록

- **동작**: 여행을 만들고, 목록에서 골라 열고, 이름을 고치거나 지운다. 공유받은 여행도 같은 목록에 섞어서 보여 주되, 공유받은 여행임을 구분해 표시한다.
- **완료 기준**: 여행을 2개 이상 만들고 서로 오가며 열 수 있다. 여행 이름을 고치고, 여행을 지울 수 있다.
- **의존**: R-01

## 4. 관련 화면 (`02-FRONTEND.md`)

- 로그인: 구글 로그인 버튼
- 여행 목록: 내 여행과 공유받은 여행이 한 목록에 섞여 있고, 공유받은 여행은 표시로 구분한다. 새 여행 만들기, 이름 수정, 삭제
- 흐름: 로그인 → 여행 목록 → (새 여행 만들기 또는 선택) → 여행 상세 1화면
- 어느 화면에서든 로그아웃 → 로그인 화면

## 5. 관련 데이터·권한 (`04-DB.md`)

- 사용자: Supabase Auth가 관리 (구글 계정 식별값, 이메일, 이름)
- 여행: 소유자, 제목, 목적지, 시작일·종료일, 동행 인원, 만든 시각, 고친 시각
- 여행은 소유자만 만들고, 고치고, 지울 수 있다.
- 여행을 지우면 그 여행의 항목과 공유 정보도 함께 지운다.

## 6. 관련 결정 (`decisions.md`)

- 범위: 여행 이름 수정·삭제를 ② 여행 목록에 추가한다.
- 목록: 공유받은 여행은 같은 목록에 섞고, 구분 표시만 한다.
- Q4: v1.0은 구글 계정만 지원한다.
- S2: 데이터 읽기·쓰기는 로그인 사용자 권한의 Supabase 클라이언트로 한다.

## 7. 층별 설계

### 7-1. R-01 구글 로그인 (v0.2)

| 층 | 파일 | 내용 |
|---|---|---|
| 화면 | `src/app/login/page.tsx` | 로그인 화면. 이미 로그인했으면 `next`로 보낸다. |
| 화면 | `src/app/login/google-login-button.tsx` | `signInWithOAuth({ provider: "google" })`. 돌아올 주소는 `/auth/callback?next=...` |
| 화면 | `src/app/page.tsx` | 첫 화면. 로그인한 이메일과 로그아웃 버튼 |
| 서버 | `src/app/auth/callback/route.ts` | 받은 코드를 세션으로 바꾸고 `next`로 보낸다. 실패하면 `/login?error=callback` |
| 서버 | `src/app/actions/auth.ts` | 로그아웃 후 `/login` |
| 서버 | `src/proxy.ts`, `src/lib/supabase/proxy.ts` | 요청마다 세션 갱신. 로그인하지 않았으면 `/login?next=원래 경로` |
| 서버 | `src/lib/auth/user.ts` | `requireUser()`. 화면마다 로그인 여부를 다시 확인한다. |
| 공통 | `src/lib/auth/redirect.ts` | 공개 경로(`/login`, `/auth/callback`), 돌아갈 경로 검사(사이트 안 경로만 허용) |

- 개발용 로그인(B3): `src/lib/auth/dev-login.ts`, `src/app/login/dev-login/`. v1.0에서 이 두 곳을 지우고, 로그인 화면의 `DevLoginButtons` 한 줄을 뺀다.
- DB: 이 단계에서는 테이블이 없다. 사용자는 Supabase Auth가 관리한다.
